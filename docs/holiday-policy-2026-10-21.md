# 节假日规则调整

日期：2026-10-21。范围：`dsh-token-cost`、共享计费规则、`dsh-sidebar-clock`。

## 采用的规则

1. 自动日历只请求当前北京时间年份。即使接口一次返回多年数据，也只接收本年度日期，不预取下一年。
2. 不对尚未公布的假期进行估算。移除固定节日日期、连续假期长度等自动补全；手动配置的日期仍作为明确输入。
3. 没有已知节假日时，按原有周末和峰谷时段规则判断，不能简单地全部算作高峰。
4. 侧边栏只查找本年度剩余的已知假期；没有时显示“暂无”，不显示“今天”或推算下一年假期。

Host 的年份边界使用 `holidayOffsetMinutes`（默认北京时间 UTC+8）；侧边栏固定使用北京时间。自定义该设置仍会改变 Host 的年份和日期判定。

## 刷新、失败和缓存

| 场景 | 行为 |
|---|---|
| 合法响应，包含日期 | 使用本年度已知日期；不补齐未返回的假期 |
| 合法空日历 | 作为成功结果，清空旧的自动日期；保留本年度手动日期 |
| HTTP 错误、业务错误码、无法识别的结构、无效日期 | 作为失败处理，不更新成功时间，不覆盖最近成功的数据 |
| 从未取得过有效日历 | 保持空日历，不生成后备假期 |
| 跨年时请求仍未完成 | 丢弃上一年返回的数据；后续刷新请求新年度 |
| 侧边栏恢复缓存 | 仅接受 v2、本年度的有效缓存，同一年内不因 14 天期限丢弃已知数据 |
| 侧边栏旧版 v1 缓存 | 忽略；该格式混合了来源日期和估算日期，无法可靠区分 |

费用插件继续使用失败退避：5 分钟、15 分钟、之后每小时；成功后恢复默认 24 小时刷新。
侧边栏继续每 6 小时刷新。跨年后无需提前查询下一年，但新年度日历可能要等到下一次刷新才取得。

支持原来的普通日期数组、`dates` 对象、Nager 日期对象数组和 timor `holiday` 对象。
日期现在必须是实际存在的 `YYYY-MM-DD`，例如 `2026-02-30` 会使本次响应失败。
timor 的 `holiday: false` 不进入假日集合；周末规则仍沿用原实现。
“已知日期”指配置来源或用户手动提供的日期，本次没有新增对来源是否确已官方公布的外部核验。

## 历史费用兼容

共享规则版本升为 3，新快照记录 `holidayPolicyVersion: 3`，不再生成 `fixed` 日期。
`holidayProvenance.fixed` 字段保留用于兼容和展示历史记录，新日历中始终为空。

旧投影检查点恢复时，在本次插件激活时间追加规则分段：保留当时费率及已经记账的 token、金额和峰谷分类；后续请求使用去掉估算日期的新规则。本次不提高投影 `stateVersion`，避免仅为更改节假日政策就强制重算历史。

该兼容针对仍存在的检查点。检查点缺失、失效或被强制重建时，原有费率历史无法完整恢复的问题（审查 R8）仍然存在，本次未修复。重试跨时段计费问题（R3）也仍待处理。
